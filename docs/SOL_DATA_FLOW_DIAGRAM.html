4. Flow: Daily push cron fire (mỗi 5 phút)

sequenceDiagram participant C as Cron */5 min participant F as fireDuePushes participant D as Database participant T as ZaloTemplate participant O as oaClient participant Z as Zalo ZNS API actor U as 👤 User C->>F: Trigger F->>D: SELECT ScheduledPush
WHERE scheduledAt <= NOW()
AND status='pending'
LIMIT 50 D-->>F: 17 pending pushes loop For each push F->>D: READ User + messagingProfile (mute check) alt User muted/paused F->>D: UPDATE ScheduledPush.status='cancelled' else User active F->>D: UPDATE ScheduledPush.status='sending' (lock) F->>T: READ ZaloTemplate WHERE code=? alt Template chưa APPROVED F->>D: UPDATE status='failed'
errorCode='TEMPLATE_NOT_APPROVED' else Template OK F->>O: znsSendTemplate(phone, templateId, params) O->>Z: POST /message/template Z-->>O: { ok, messageId } alt Success F->>D: CREATE ZNSLog (status=SENT) F->>D: UPDATE ScheduledPush.status='sent', znsLogId, sentAt F->>D: UPSERT UserMessagingProfile.totalSent++ Z-->>U: User nhận tin daily chip else Fail F->>D: UPDATE ScheduledPush.status='pending'
retryCount++
scheduledAt += backoff Note over F: Exponential backoff:
2, 4, 8 phút end end end end F-->>C: { scanned, sent, failed, skipped }
📝 Note: Cron mỗi 5 phút mới fire. Nếu user chọn preferredPushHour=7, push sẽ thực sự fire trong khoảng 7:00-7:05.

Cost mỗi tin0đ~ 300đ/tin ZNS

Rich UI✓ React fullText + 3 button max

Workbook journal✓ Editor đầy đủChỉ chat text
Crisis 90s timer✓ Visual countdownText "đếm 1,2,3..."
🎯 Best practice:
  • Zalo OA → cho push (Sol nhắc anh hằng ngày qua phone notification)
  • Web Widget → cho deep work (workbook, voice, AI chat sâu, checkin chi tiết)
User dùng cả 2 cùng lúc — Zalo nhận push, click link wiki → vào sol.vn → widget tự nhận diện user (qua bind Zalo) → tiếp tục chat sâu hơn.

6. Flow: Lapse Event Recovery

Khi user "Tôi đã hút 1 điếu" (lapse) — Sol chuyển sang recovery mode (KHÔNG kết tội, KHÔNG cancel journey).

sequenceDiagram actor U as 👤 User participant A as App bothuocla.sol.vn participant API as /api/lapse participant D as Database participant J as journeyEngine participant O as oaClient participant Z as Zalo OA U->>A: Click "Tôi đã hút 1 điếu" (lapse log) A->>API: POST /api/lapse { count: 1, time, context } API->>D: CREATE LapseEvent (userId, time, count, context) API->>D: CREATE CigaretteLog (userId, count, day) alt Lapse > threshold (vd 3 điếu/ngày) API->>J: Đánh dấu relapsed J->>D: UPDATE User.journeyStatus='relapsed' J->>D: UPDATE ScheduledPush WHERE status='pending' SET status='cancelled' Note over J: Re-enroll vào shorter
recovery journey (TBD) end API->>O: oaSendText(SOL_LAPSE_RECOVERY template) O->>Z: ZNS template Z->>U: "1 lapse ≠ relapse. 70% phục hồi (Marlatt). Tiếp tục anh nhé"
🎯 Triết lý lapse: Theo Marlatt 1985, 70% user phục hồi sau 1 lapse nếu KHÔNG bị tự đánh giá. Sol không cancel journey — chỉ note + encouragement.
